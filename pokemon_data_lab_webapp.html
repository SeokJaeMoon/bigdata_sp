A / 웹페이지의 데이터는 어떻게 생겼을까?

수집 대상의 표 구조를 단순화한 HTML 예시. 크롤러는 행과 열을 찾아 값을 읽는다.

<table id="pokedex">
  <tbody>
   <tr>
    <td>0001</td>
    <td>Bulbasaur</td>
    <td>Grass/Poison</td>
    <td>318</td>
    <td>45,49,49,65,65,45</td>
   </tr>
  </tbody>
</table>

실시간 공개 웹페이지 크롤링은 Google Colab 노트북에서 `requests + BeautifulSoup`로 실행한다. 브라우저의 사이트 간 접근 제한(CORS) 때문에 이 HTML 파일은 외부 웹페이지를 직접 크롤링한다고 주장하지 않는다.

AFTER THE LAB

스스로 생각해 보기.

관찰한 숫자보다 중요한 것은 왜 그런 결과가 나왔는지 질문하는 태도다.

MISSION / 01

데이터가 많으면 늘 정답일까?

스몰/전체 모드를 바꾸고 스피드 순위와 평균이 달라지는 이유를 설명해 보자.

MISSION / 02

공격력 150이면 빠를까?

공격 특화 버튼을 누르고 예상 스피드, 가장 가까운 다섯 캐릭터를 확인해 보자.

MISSION / 03

편향이 있는 데이터라면?

샘플은 스타터 포켓몬 중심이다. 전체를 대표하지 못하는 편의표본이 예측에 미칠 영향을 토론한다.

교육용 데이터 과학 실습

코드 없는 브라우저 실습은 HTML 샘플의 DOM 파싱과 CSV 업로드를 수행합니다. 외부 서버 크롤링은 CORS 제약으로 인해 Python Google Colab에서 별도로 수행합니다. HTML 파일은 외부 CDN과 서버가 필요 없는 독립 실행형입니다. 기존 게임 콘텐츠의 특성상 이 데이터는 통계 학습용일 뿐 실제 향후 출시 데이터나 제작사 예측을 의미하지 않습니다.
